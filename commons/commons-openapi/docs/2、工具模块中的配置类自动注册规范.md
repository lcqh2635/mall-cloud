## ✅ 你的问题本质是：

> **“`commons-openapi` 模块中定义了 `@Configuration` 类（如 `OpenApiConfig`、`OpenApiBaseConfig`），但业务模块引入它后，这些配置类不会被自动扫描注册到 Spring 容器，导致功能失效。如何确保它们能被自动加载？”**

### 🔍 答案：**是的，缺少一个自动配置类（Auto-Configuration）！**

虽然你在 `commons-openapi` 中写了 `@Configuration` 类，但 Spring Boot **默认不会自动扫描第三方 JAR 中的 `@Configuration` 类**，除非：

1. 它们在 `@ComponentScan` 的包路径下（通常不现实）
2. 或者——**你使用了 Spring Boot 的 `spring.factories` 自动配置机制**

> ❌ 如果你不加自动配置，业务模块引入 `commons-openapi` 后：
> - `OpenApiConfig` 不会被加载
> - `ApiInfo`、公共模型注册、全局 Header 都不会生效
> - 开发者必须手动在每个服务中再写一遍 `@EnableOpenApi` + 手动注册 Bean → **违背了你设计初衷！**

---

# ✅ 正确解决方案：添加 `spring.factories` 自动配置类

---

## ✅ 最终修正方案：**在 `commons-openapi` 中添加 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 文件**

这是 Spring Boot 2.7+ 推荐的 **新一代自动配置机制**（替代旧版 `spring.factories`）。

> - 路径必须是：`src/main/resources/META-INF/spring/`
> - 每行写一个完整的全限定类名
> - 不需要 `@Configuration` 注解也能被加载 —— 这就是它的作用！

## ✅ 为什么这个文件如此重要？

| 机制 | 是否自动加载 `@Configuration` | 是否推荐 | 说明 |
|------|-----------------------------|----------|------|
| `@ComponentScan` | ✅ 是 | ❌ 不推荐 | 必须指定包，破坏模块化 |
| `@Import` | ✅ 是 | ❌ 不推荐 | 每个业务模块仍需手动写 `@Import(OpenApiConfig.class)` |
| `spring.factories`（旧版） | ✅ 是 | ⚠️ 已废弃 | Spring Boot 2.7+ 开始弃用 |
| ✅ `AutoConfiguration.imports`（新版） | ✅ 是 | ✅ **官方推荐** | 无侵入、无配置、零感知，完美契合你的需求 |

> ✅ 使用 `AutoConfiguration.imports`，业务模块只需：
> ```xml
> <dependency>
>     <groupId>io.urbane</groupId>
>     <artifactId>commons-openapi</artifactId>
> </dependency>
> ```
> **无需任何额外代码，所有 OpenAPI 配置就自动生效！**
