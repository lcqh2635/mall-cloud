这是一个专为您的 `mall-cloud` 微服务架构设计的 Redis ACL 配置文件示例。它遵循了**最小权限原则**，将不同微服务的权限严格隔离，以防止一个服务出现
Bug 或遭受攻击时影响其他服务。

### 📄 文件路径: `/etc/redis/users.acl`

```conf
# =============================================================================
# Redis ACL 配置文件 (users.acl)
# 适用项目: mall-cloud 微服务电商系统
# 维护者: 运维/架构组
# =============================================================================

# 【全局说明】
# 每一行代表一个用户配置。
# 语法结构: user <用户名> <状态> <密码> <键权限> <命令权限>
# 示例: user admin on >123456 ~* +@all
#       ^    ^     ^   ^      ^    ^
#       |    |     |   |      |    └─ 命令权限 (允许所有命令)
#       |    |     |   |      └────── 键权限 (允许访问所有键)
#       |    |     |   └────────────── 密码 (明文 123456)
#       |    |     └────────────────── 状态 (on 开启)
#       |    └──────────────────────── 用户名 (admin)
#       └────────────────────────────── 关键字

# =============================================================================
# 1. 默认用户 (Default User)
# 安全建议：生产环境中强烈建议禁用默认用户，强制所有服务使用命名用户登录。
# =============================================================================
# off: 禁用该用户，拒绝任何未指定用户名的连接
user default off

# 备用方案（如果需要保留默认用户做本地调试）：
# user default on >Redis@DefaultPass ~* +@all -@dangerous
# (开启 + 密码 + 所有键 + 所有命令 - 危险命令)


# =============================================================================
# 2. 超级管理员 (Super Admin)
# 用途：仅供运维人员、DBA 或自动化脚本使用。
# =============================================================================
# - on: 启用
# - >Super@Secure#2026: 设置强密码（明文，建议后续替换为 SHA256 哈希值）
# - ~*: 允许访问所有 Key
# - +@all: 允许执行所有命令
# - +@admin: 显式允许管理命令
# - +@dangerous: 允许执行危险命令（如 FLUSHALL, KEYS, DEBUG 等）
user admin on >Super@Secure#2026 ~* +@all +@admin +@dangerous


# =============================================================================
# 3. 订单服务 (Order Service)
# 对应微服务: order-service
# 业务场景: 处理订单创建、支付状态查询。需要读写订单数据，且有时需要关联查询用户基础信息。
# =============================================================================
# - ~order:*: 允许访问以 "order:" 开头的所有键 (如 order:1001)
# - ~user:profile:*: 允许访问用户档案数据 (用于订单详情展示买家信息)
# - +@read: 允许读操作 (GET, HGET, LRANGE...)
# - +@write: 允许写操作 (SET, HSET, LPUSH...)
# - +@transaction: 允许事务操作 (MULTI, EXEC)
# - -FLUSHALL: 严禁清空数据库
# - -CONFIG: 严禁修改 Redis 配置
# - -KEYS: 严禁使用 KEYS 命令 (防止阻塞主线程)
user order-service on >Order@2026! ~order:* ~user:profile:* +@read +@write +@transaction -FLUSHALL -CONFIG -KEYS


# =============================================================================
# 4. 用户/认证服务 (User & Auth Service)
# 对应微服务: user-service, auth-server
# 业务场景: 用户注册登录、JWT Token 管理、黑名单、Session 存储。
# =============================================================================
# - ~user:*: 允许操作用户数据
# - ~auth:*: 允许操作认证数据
# - ~session:*: 允许操作会话数据
# - ~token:blacklist:*: 允许操作 Token 黑名单 (退出登录用)
# - +@all: 由于是核心数据源，给予该服务较全的权限，但排除危险操作
# - -@dangerous: 禁止危险命令
user auth-service on >Auth@Service! ~user:* ~auth:* ~session:* ~token:blacklist:* +@all -@dangerous


# =============================================================================
# 5. 购物车服务 (Cart Service)
# 对应微服务: cart-service
# 业务场景: 用户购物车数据的增删改查。
# =============================================================================
# - ~cart:*: 仅允许访问购物车数据
# - +@write: 允许写入
# - +@read: 允许读取
# - +H*: 特别允许 Hash 操作 (HSET, HGET, HDEL, HGETALL)，购物车通常用 Hash 存储
# - -KEYS: 禁止扫描所有键
# - -FLUSH*: 禁止清空
user cart-service on >Cart@2026 ~cart:* +@write +@read +H* -KEYS -FLUSHALL -FLUSHDB


# =============================================================================
# 6. 商品/缓存服务 (Product Service)
# 对应微服务: product-service
# 业务场景: 商品详情缓存、类目树缓存。通常是写少读多。
# =============================================================================
# - ~product:*: 商品数据
# - ~category:*: 类目数据
# - ~inventory:cache:*: 库存缓存数据 (注意：扣减库存通常走数据库或分布式锁，这里仅存缓存)
# - +GET +MGET: 允许读取
# - +SET +MSET: 允许写入 (用于更新缓存)
# - +EXPIRE +TTL: 允许管理缓存过期时间
# - -DEL: 限制随意删除，防止缓存被意外击碎 (可根据实际需求开启)
user product-service on >Product@Cache! ~product:* ~category:* ~inventory:cache:* +GET +MGET +SET +MSET +EXPIRE +TTL


# =============================================================================
# 7. 监控与报表 (Monitoring & Analytics)
# 对应组件: Prometheus Exporter, Grafana, 报表系统
# 业务场景: 读取 Redis 状态指标、慢日志、或只读的业务统计数据。
# =============================================================================
# - ~stats:*: 统计数据
# - ~metrics:*: 监控指标
# - +INFO: 允许查看服务器信息 (INFO 命令)
# - +PING: 允许心跳检测
# - +SLOWLOG: 允许查看慢查询日志 (用于性能分析)
# - +@read: 允许读取业务数据
# - -@write: 禁止任何写入操作 (确保数据安全)
user monitor-readonly on >Monitor@Read! ~stats:* ~metrics:* +INFO +PING +SLOWLOG +@read -@write


# =============================================================================
# 8. 内部消息/通知服务 (Notification Service)
# 对应微服务: notification-service
# 业务场景: 邮件、短信队列，WebSocket 消息。
# =============================================================================
# - ~queue:email:*: 邮件队列
# - ~queue:sms:*: 短信队列
# - ~ws:session:*: WebSocket 会话状态
# - +LPUSH +RPUSH: 允许推入队列 (生产者)
# - +LPOP +RPOP: 允许弹出队列 (消费者)
# - +LLEN: 查看队列长度
# - -GET: 禁止获取普通字符串 (因为主要是列表操作)
user notification-service on >Notify@Svc! ~queue:email:* ~queue:sms:* ~ws:session:* +LPUSH +RPUSH +LPOP +RPOP +LLEN -GET


# =============================================================================
# 配置说明总结
# =============================================================================
# 1. 键模式 (~): 使用通配符 * 限制服务只能访问特定前缀的 Key。
# 2. 命令类别 (+@):
#    - @read: 读操作 (GET, HGET...)
#    - @write: 写操作 (SET, HSET...)
#    - @admin: 管理命令 (CONFIG, REPLICAOF...)
#    - @dangerous: 危险命令 (FLUSHALL, KEYS, DEBUG...)
#    - @transaction: 事务 (MULTI, EXEC...)
#    - @blocking: 阻塞命令 (BLPOP, XREAD...)
# 3. 密码安全:
#    - >password: 明文密码 (方便配置，但需保护文件权限 600)
#    - #hash: SHA256 哈希 (更安全，使用 redis-cli ACL SETUSER <user> #<hash> 生成)

```

### ️ 安全建议

1. **文件权限**：
   务必确保此文件对操作系统的其他用户不可读，因为它包含明文密码。
   ```bash
   sudo chown redis:redis /etc/redis/users.acl
   sudo chmod 600 /etc/redis/users.acl
   ```

2. **加载配置**：
   修改此文件后，如果未重启 Redis，需要在 `redis-cli` 中执行：
   ```bash
   ACL LOAD
   ```

3. **生产环境密码**：
   上述配置中的密码（如 `>Order@2026!`）仅为示例。在实际部署时，建议使用 `ACL SETUSER <username> >NewStrongPassword`
   生成密码，或者直接使用 SHA256 哈希值 `#...`，避免在配置文件中留下明文密码痕迹。
