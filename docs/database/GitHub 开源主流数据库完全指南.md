## 1. 关系型数据库 (RDBMS)

### 1.1 PostgreSQL
**GitHub**: https://github.com/postgres/postgres  
**Stars**: 21k+  
**语言**: C

#### 作用
企业级对象关系型数据库，支持复杂查询、事务、扩展性。

#### 核心特点
- ✅ **ACID 事务**：完全支持
- ✅ **SQL 标准兼容**：最接近 SQL 标准的开源实现
- ✅ **扩展性强**：支持自定义数据类型、函数、操作符
- ✅ **JSON/JSONB**：原生支持半结构化数据
- ✅ **GIS 支持**：PostGIS 扩展（地理信息处理）
- ✅ **并行查询**：多核并行执行
- ✅ **MVCC**：多版本并发控制
- ✅ **流复制**：主从同步、逻辑复制

#### 使用场景
- 📊 复杂业务系统（ERP、CRM）
- 🗺️ 地理信息系统（GIS）
- 📈 数据分析与报表
- 🔐 需要强一致性的金融系统
- 🧩 需要自定义扩展的场景

#### 性能指标
- 并发连接：数百到数千
- 单表数据量：亿级
- 写入性能：10k+ TPS（单机）
- 查询延迟：毫秒级

### 1.2 MySQL / MariaDB
**GitHub**:
- MySQL: https://github.com/mysql/mysql-server
- MariaDB: https://github.com/MariaDB/server  
  **Stars**: 12k+ (MySQL), 7k+ (MariaDB)  
  **语言**: C/C++

#### 作用
最流行的开源关系型数据库，Web 应用首选。

#### 核心特点
- ✅ **易用性**：安装配置简单，学习成本低
- ✅ **生态丰富**：最广泛的 ORM、工具支持
- ✅ **复制机制**：主从复制、组复制（MGR）
- ✅ **存储引擎**：InnoDB（事务）、MyISAM（读多写少）
- ✅ **分区表**：支持范围、列表、哈希分区
- ✅ **JSON 支持**：MySQL 5.7+ 原生支持
- ✅ **Galera Cluster**：多主同步（MariaDB）

#### 使用场景
- 🌐 Web 应用（WordPress、Drupal）
- 📱 移动应用后端
- 🛒 电商系统
- 📝 内容管理系统（CMS）
- 🔧 中小型业务系统

#### 性能指标
- 并发连接：数千
- 单表数据量：千万到亿级（需分区）
- 写入性能：5k-15k TPS
- 查询延迟：亚毫秒到毫秒级

### 1.3 TiDB
**GitHub**: https://github.com/pingcap/tidb  
**Stars**: 40k+  
**语言**: Go

#### 作用
NewSQL 分布式数据库，兼容 MySQL 协议，支持 HTAP。

#### 核心特点
- ✅ **水平扩展**：自动分片（Region），在线扩容
- ✅ **强一致性**：基于 Raft 协议
- ✅ **MySQL 兼容**：无缝迁移 MySQL 应用
- ✅ **HTAP**：TiKV（行存）+ TiFlash（列存）
- ✅ **高可用**：多副本、自动故障转移
- ✅ **分布式事务**：Percolator 模型
- ✅ **MPP 架构**：大规模并行处理

#### 使用场景
- 📈 海量数据（百亿级）业务
- 🔄 需要水平扩展的 MySQL 应用
- 📊 实时分析 + 事务处理混合场景
- 🌍 全球化多活部署
- 💰 金融级一致性要求

#### 性能指标
- 并发连接：数万
- 单表数据量：百亿级
- 写入性能：百万级 TPS（集群）
- 查询延迟：毫秒到秒级（复杂查询）

## 3. 键值型数据库

### 3.1 Redis
**GitHub**: https://github.com/redis/redis  
**Stars**: 74k+  
**语言**: C

#### 作用
内存键值存储，支持持久化，常用作缓存、消息队列。

#### 核心特点
- ✅ **数据结构丰富**：String、Hash、List、Set、Sorted Set、Bitmap、HyperLogLog、Geo

- ✅ **Lua 脚本**：原子操作
- ✅ **集群模式**：Redis Cluster 自动分片
- ✅ **过期策略**：TTL 自动删除

#### 使用场景
- ⚡ 缓存（数据库查询结果）
- 🔢 计数器（点赞、浏览量）
- 🏆 排行榜（Sorted Set）
- 🔐 分布式锁
- 💬 消息队列（List/Pub-Sub）
- 🛒 购物车（Hash）
- 📍 地理位置（Geo）

#### 性能指标
- 并发连接：数万
- 读写延迟：亚毫秒级
- QPS：10万+（单机）
- 内存占用：取决于数据量

        │
数据量？┼─ < 100GB → 单机数据库（PostgreSQL / MySQL）
        │

        │   ├─ < 1000 QPS → 传统 RDBMS

        │

## 13. 2026 年趋势建议

### 📈 新兴趋势
1. **HTAP 融合**：TiDB、OceanBase 同时处理 OLTP + OLAP
2. **云原生优先**：K8s Operator、Serverless 数据库
3. **AI 集成**：向量数据库成为 AI 应用标配
4. **多模型统一**：单一数据库支持多种数据模型
5. **边缘计算**：轻量级数据库（SQLite、LiteFS）

### 🎯 选型建议
- **新系统**：优先考虑云原生分布式数据库（TiDB、CockroachDB）
- **AI 应用**：必须集成向量数据库（Milvus、Chroma）
- **IoT/监控**：专用时序数据库（TDengine、InfluxDB）
- **搜索需求**：Elasticsearch 仍是行业标准
- **缓存层**：Redis 不可替代
- **简单应用**：PostgreSQL 足够应对 90% 场景

**📌 核心原则**：
> **没有"最好"的数据库，只有"最适合"的数据库。**  
> 根据数据模型、一致性要求、扩展性需求、团队技能综合选择。  
> 微服务架构下，**多数据库共存（Polyglot Persistence）** 是常态。
