

### utf8mb4_unicode_ci和utf8mb4_general_ci推荐使用哪一个？

推荐使用 `utf8mb4_unicode_ci`。

虽然 `utf8mb4_general_ci` 也是一种常用的排序规则，但它对于某些特殊字符的排序和比较可能会产生一些不准确的结果。主要区别在于 `utf8mb4_unicode_ci` 对 Unicode 字符进行了更精确的排序和比较，而 `utf8mb4_general_ci` 则更加宽松。

`utf8mb4_unicode_ci` 使用了更复杂和准确的规则来处理字符排序，因此在多语言环境下更适用。它考虑了字符的重音符号、大小写变化、特殊字符等，并且对各种语言都提供了一致的排序结果。如果你的应用需求涉及多语言，特别是需要准确的排序和比较操作，那么 `utf8mb4_unicode_ci` 是更好的选择。

相比之下，`utf8mb4_general_ci` 虽然性能上稍微快一些，但它没有像 `utf8mb4_unicode_ci` 那样处理字符的精确性和全面性。在某些情况下，`utf8mb4_general_ci` 可能会导致不正确的排序结果，尤其是在针对一些特殊字符或特定语言的数据进行排序和比较时。

因此，为了确保良好的排序和比较行为，尤其是在多语言环境下，强烈建议使用 `utf8mb4_unicode_ci`。这样可以避免一些潜在的问题，同时保持数据的一致性和准确性。

### 如下创建数据库，还需要额外为表字段设置使用utf8mb4_unicode_ci吗？

```mysql
CREATE DATABASE database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; 
```

在使用以下方式创建数据库时：

```sql
CREATE DATABASE database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**不需要再额外设置字段的字符集和校对规则。创建数据库时指定了字符集和校对规则，该设置将应用于数据库中的所有表和列。**

当你在创建表时，可以直接定义字段的数据类型和其他属性，无需再次指定字符集和校对规则。例如：

```sql
CREATE TABLE table_name (
   column_name VARCHAR(50),
   ...
);
```

上述示例中的 `column_name` 字段将默认使用在创建数据库时指定的字符集和校对规则（`utf8mb4_unicode_ci`），除非有特定需求需要覆盖默认设置，否则不需要额外设置字符集和校对规则。

通过在创建数据库时指定字符集和校对规则，以及在创建表时直接定义字段，可以确保整个数据库的一致性，并避免在每个表和每个字段上重复设置字符集和校对规则。

### 还需要再使用SET NAMES utf8mb4 ;吗？

在创建数据库时使用 `SET NAMES utf8mb4;` 是一种设置字符集的常见方式，但实际上并不需要在创建数据库后再次使用它。

当你使用以下语句创建数据库时：

```sql
CREATE DATABASE database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

该语句已经指定了数据库的字符集为 `utf8mb4`。这意味着在创建数据库之后，所有与该数据库相关的连接和查询都将默认使用 `utf8mb4` 字符集。

因此，在执行 `CREATE DATABASE` 语句后，通常不需要再单独执行 `SET NAMES utf8mb4;`。该语句已经在创建数据库时设置好了。

`SET NAMES utf8mb4;` 语句主要用于在每个数据库连接中设置字符集。如果你使用的是应用程序框架或客户端工具，它们可能会自动为每个新的数据库连接执行 `SET NAMES utf8mb4;` 或者对字符集进行正确的配置。

综上所述，**如果你已经在创建数据库时明确指定了字符集为 `utf8mb4`，那么通常情况下无需再使用 `SET NAMES utf8mb4;` 语句。**只需要确保应用程序或客户端工具正确地处理数据库连接和字符集配置即可。

### 为什么数据库名、表名、字段名使用反引号包裹而不是单引号或双引号？

实际上，在MySQL中，数据库名、表名和字段名应该使用反引号（`` ` ``）进行包裹，而不是使用单引号或双引号。

**使用反引号的原因是为了避免与保留字（reserved words）冲突**。保留字是在MySQL中具有特殊含义的关键字，如SELECT、INSERT、UPDATE等。如果您使用保留字作为数据库名、表名或字段名，并且不使用任何分隔符来区分它们，那么MySQL将会解析这些保留字并将其视为关键字，导致语法错误的发生。

通过使用反引号，您可以告诉MySQL将名称视为普通的标识符而不是保留字。例如，如果您想创建一个名为`table`的表，那么可以使用反引号来避免与保留字冲突：

```sql
CREATE TABLE `table` ( ... );
```

需要注意的是，反引号只是一种用于标识符的分隔符，而不是字符串的引号。字符串值应使用单引号或双引号括起来。例如：

```sql
INSERT INTO `table` (`column`) VALUES ('value');
```

总之，反引号是用于在MySQL中标识数据库名、表名和字段名的分隔符，以避免与保留字冲突。

### UNIQUE KEY的作用

`UNIQUE KEY` 是用于在数据库表中创建唯一性约束的关键字。**通过使用 `UNIQUE KEY`，您可以确保在指定的列或列组合中不会出现重复的值，可以实现数据防重**

以下是一个示例，演示了如何在 `CREATE TABLE` 语句中使用 `UNIQUE KEY`：

```sql
CREATE TABLE table_name (
    column1 datatype,
    column2 datatype,
    ...
    UNIQUE KEY constraint_name (column1, column2)
);


# 也可显示指定索引类型，默认是 BTREE
UNIQUE KEY constraint_name (column1, column2) USING BTREE

# 请注意，对于大多数数据库系统，B-tree 是默认的索引类型，因此如果不显式地指定索引类型，通常会自动使用 B-tree 索引。
```

在这个示例中，我们在表 `table_name` 中创建了一个名为 `constraint_name` 的唯一性约束，该约束应用于 `column1` 和 `column2` 这两列。这意味着在这两列中的组合值必须是唯一的，不允许重复。

在创建 `UNIQUE KEY` 时，确实需要为约束指定一个名称。`constraint_name` 是用于表示约束名称的占位符，您可以自由选择一个符合命名规范的名称，以便更好地理解和管理数据库结构。

对于约束名称，您可以根据自己的需求进行命名，但需要遵循以下规则：

- 名称必须是唯一的，不与其他表或约束的名称冲突。
- 名称最好能够反映约束的含义或目的，以方便他人理解和维护数据库结构。

请记住，尽管约束名称是可选的，但为了更好地组织和管理数据库，以及为了提高代码可读性，建议始终为约束命名。

您可以根据需要，在表的定义中使用多个 `UNIQUE KEY` 来创建不同的唯一性约束。如果要命名约束，可以将约束名称放在括号中。

值得注意的是，**`UNIQUE KEY` 不同于主键（Primary Key）。主键是一种特殊的唯一性约束，它还具有额外的属性，例如自动增长（Auto Increment）和非空（Not Null）。如果需要在表中定义主键，请使用 `PRIMARY KEY` 关键字。**

### 什么是外键？，什么是主键？

外键（Foreign Key）和主键（Primary Key）是关系型数据库中两个重要的概念。

主键是用于唯一标识表中每一行数据的字段或字段组合。它必须具有唯一性且不能包含空值。主键在表中应该是唯一的，用于确保表中的数据可以被唯一地识别和访问。常见的主键类型包括自增整数、全局唯一标识符（GUID）等。

外键是用于建立表与表之间关联关系的字段，**它通过指向其他表中的主键来实现关联**。外键在一张表中是另一张表的主键。外键可以用来保持表与表之间的数据完整性，以及实现数据之间的引用和约束。通过外键，可以在关联的表之间建立引用关系，从而进行查询、更新和删除操作时维护数据的完整性。

举例来说，假设有两张表：学生表和班级表。学生表中有一个字段为学生ID作为主键，班级表中有一个字段为班级ID作为主键。在学生表中，可以添加一个外键字段"班级ID"，它指向班级表的主键"班级ID"。这样，就建立了学生表和班级表之间的关联关系，学生表中的每个学生的"班级ID"字段都必须指向班级表中已经存在的班级ID。

通过使用外键和主键，可以在关系型数据库中建立复杂的关联关系，确保数据的一致性和完整性。

### 推荐使用外键吗？

使用外键是一种良好的数据库设计实践，并且在大多数情况下是值得推荐的。

以下是使用外键的几个好处：

1. 数据完整性：使用外键可以确保表与表之间的数据关联和引用的完整性。外键可以防止插入无效的数据，保持数据的一致性和准确性。

2. 数据一致性：外键可以帮助维护表与表之间的关联关系，确保在更新或删除操作时没有产生不一致的数据。它可以提供自动的级联更新或级联删除功能，使相关数据得到同步维护。

3. 查询优化：外键可以帮助进行高效查询和关联操作。通过使用外键，可以轻松地获取关联表中的数据，避免手动编写复杂的查询条件。

4. 文档化关系：外键可以促使开发人员和数据库管理员更清晰地了解表之间的关系和依赖。它可以作为文档的一部分，有助于他人理解数据库结构和数据流。

然而，使用外键也需要注意以下几点：

1. 性能影响：使用外键可能会对性能产生一定的影响。特别是在大规模的数据操作时，外键约束的检查和维护可能会导致额外的开销。在某些情况下，可以根据具体需求权衡性能和数据完整性之间的平衡。

2. 设计复杂性：外键关系可能会增加数据库设计的复杂性。需要仔细考虑表之间的关系，确保正确定义外键，并处理好级联更新或删除的规则。

综上所述，尽管使用外键可能带来一些开销和复杂性，但通常情况下仍然建议使用外键来维护数据的完整性和一致性。它可以帮助减少错误和数据不一致的风险，并提供更有效的查询和关联操作。

### SET FOREIGN_KEY_CHECKS = 0;的作用

`SET FOREIGN_KEY_CHECKS = 0;` 是一条 MySQL 语句，**用于禁用外键约束检查。外键将失效**。当执行这条语句后，MySQL 将不再对当前会话中的外键约束进行检查。

在某些情况下，你可能希望禁用外键约束检查。例如，在进行大规模数据导入或删除操作时，禁用外键约束可以提高操作的性能和效率。

然而，需要注意的是，禁用外键约束可能会导致数据的一致性问题。如果在禁用外键约束时进行了不符合外键约束的操作，可能会导致数据库中存在无效的关联关系。

因此，在使用 `SET FOREIGN_KEY_CHECKS = 0;` 禁用外键约束之前，请确保你已经了解了操作的后果，并在必要时采取其他措施来保持数据的完整性和一致性。同时，还应该在完成需要禁用外键约束的操作后，显式地启用外键约束，即执行 `SET FOREIGN_KEY_CHECKS = 1;`，以确保数据的一致性得到恢复。

`SET FOREIGN_KEY_CHECKS = 0;` 不会将外键字段变为普通字段。这个语句只是暂时禁用了数据库对于外键约束的检查，删除或修改主表中的记录时不会触发错误。但是，该字段仍然保持其定义为外键的属性。

总而言之，虽然可以使用 `SET FOREIGN_KEY_CHECKS = 0;` 来禁用外键约束检查，但应谨慎使用，并确保在执行相关操作后及时启用外键约束，以保持数据的完整性和一致性。

#### 查看数据库自身的信息

要查看数据库自身的信息，你可以使用数据库管理系统提供的一些系统表或系统视图来获取数据库的元数据信息。这些系统表或系统视图存储了关于数据库结构、对象和配置的信息。以下是一些常见的方法来查看数据库自身的信息：

1. MySQL数据库：
   - 使用SHOW DATABASES语句可以列出所有可用的数据库：
     ```
     SHOW DATABASES;
     ```

   - 使用SHOW VARIABLES语句可以查看数据库服务器的配置参数：
     ```
     SHOW VARIABLES;
     ```

   - 使用SHOW STATUS语句可以查看数据库服务器的状态信息：
     ```
     SHOW STATUS;
     ```

2. Oracle数据库：
   - 使用SELECT语句从系统视图中获取数据库信息，例如，可以查询`V$DATABASE`视图获取数据库的基本信息：
     ```
     SELECT * FROM V$DATABASE;
     ```

   - 使用SELECT语句查询`V$PARAMETER`视图可以查看数据库的参数配置信息：
     ```
     SELECT * FROM V$PARAMETER;
     ```

   - 使用SELECT语句查询`V$INSTANCE`视图可以查看数据库实例的状态信息：
     ```
     SELECT * FROM V$INSTANCE;
     ```

这些是一些示例，具体的方法和可用的系统表或系统视图可能因数据库管理系统的不同而有所差异。你可以根据使用的具体数据库管理系统的文档或参考资料来查找适用于该数据库的特定方法和系统表/视图。
