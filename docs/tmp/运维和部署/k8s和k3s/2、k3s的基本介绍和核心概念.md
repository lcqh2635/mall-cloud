# K3s 详解文档

---

## 一、K3s 是什么？

**K3s** 是由 Rancher Labs（现为 SUSE 公司的一部分）推出的一个**轻量级 Kubernetes 发行版**，专为资源受限环境（如边缘计算、IoT、ARM 设备、开发测试环境）设计。其名称中 “K3s” 的 “3” 代表 “轻量级”，是 “K8s”（Kubernetes）的简化版本。

K3s 完全兼容上游 Kubernetes API，通过移除传统 Kubernetes 中非必需的组件、使用轻量级依赖（如 SQLite 替代 etcd）、内置组件集成等方式，实现极简部署和低资源消耗。

> ✅ K3s 是 CNCF 官方认证的 Kubernetes 发行版（Certified Kubernetes Distribution）。

---

## 二、K3s 的作用

1. **轻量部署**：二进制文件 < 100MB，内存占用低（最低 512MB RAM 即可运行）。
2. **单二进制架构**：所有组件打包在一个可执行文件中，简化安装与管理。
3. **适用于边缘/IoT/ARM 设备**：支持树莓派、Jetson、工控机等低功耗设备。
4. **快速启动**：一条命令即可部署完整 Kubernetes 集群。
5. **内置组件**：默认集成 Ingress Controller（Traefik）、Service LB、本地存储、Helm Controller 等。
6. **离线安装支持**：支持 air-gap（离线）部署。
7. **高可用支持**：通过嵌入式 etcd 或外部数据库实现多 Server HA。
8. **开发友好**：本地开发、CI/CD 测试环境的理想选择。

---

## 三、K3s 核心概念

K3s 继承了 Kubernetes 的核心概念，但部分组件被替换或简化：

### 1. Server 节点（原 Master）
- 运行控制平面组件（API Server、Controller Manager、Scheduler）。
- 可部署为单节点或高可用集群。

### 2. Agent 节点（原 Worker）
- 运行工作负载（Pods），由 Server 节点调度。
- 可动态加入集群。

### 3. Pod / Deployment / Service / Ingress
- 与标准 Kubernetes 完全一致，语义和用法无变化。

### 4. 内置组件（K3s 特色）
- **Traefik Ingress Controller**：默认启用，提供 HTTP 路由。
- **Local Path Provisioner**：为 PersistentVolume 提供本地存储支持。
- **Service Load Balancer（Klipper LB）**：为 LoadBalancer 类型 Service 分配节点端口。
- **Helm Controller**：支持通过 CRD 声明式部署 Helm Chart（需启用）。
- **SQLite / etcd / MySQL / PostgreSQL**：作为集群状态存储后端。

### 5. 数据存储后端
- 默认：**SQLite**（单节点模式）
- 生产 HA：**etcd**、**MySQL**、**PostgreSQL**

### 6. 容器运行时
- 默认：**containerd**
- 支持切换为 Docker（不推荐）、CRI-O

## 四、K3s 核心组件及其作用

K3s 将传统 Kubernetes 多个组件整合为两个核心进程：**k3s server** 和 **k3s agent**。

---

### ▶ k3s server（控制平面）

在一个进程中运行以下组件：

| 组件 | 作用 | 说明 |
|------|------|------|
| **kube-apiserver** | API 入口 | 提供 Kubernetes REST API，是集群的前端网关 |
| **kube-scheduler** | 调度器 | 决定 Pod 应该运行在哪个节点 |
| **kube-controller-manager** | 控制器管理器 | 运行 Node、Deployment、ReplicaSet 等控制器 |
| **cloud-controller-manager** | 云控制器 | 可选，用于云平台集成 |
| **etcd / SQLite / External DB** | 数据存储 | 保存集群状态。默认 SQLite，HA 用 etcd 或外部数据库 |
| **Traefik Ingress Controller** | Ingress 控制器 | 默认启用，处理 HTTP/HTTPS 路由 |
| **CoreDNS** | 集群 DNS | 为 Service 和 Pod 提供域名解析 |
| **Klipper LB (Service LB)** | 负载均衡器 | 为 LoadBalancer 类型 Service 分配节点端口 |
| **Local Path Provisioner** | 存储插件 | 为 PVC 提供基于节点本地路径的 PV |
| **Metrics Server** | 资源监控 | 支持 HPA（Horizontal Pod Autoscaler） |

> 📌 所有组件默认集成在 `k3s server` 进程中，无需单独部署。

---

### ▶ k3s agent（工作节点）

运行以下组件：

| 组件 | 作用 |
|------|------|
| **kubelet** | 节点代理，管理本机 Pod 生命周期 |
| **kube-proxy** | 维护网络规则，实现 Service 访问 |
| **containerd** | 默认容器运行时，拉取并运行容器 |
| **Flannel（可选）** | CNI 插件，默认启用，提供 Pod 网络 |

> 📌 `k3s agent` 通过连接 `k3s server` 注册为工作节点。

## 六、K3s 在 Fedora 和 Ubuntu 中的安装教程

> 以下安装方式适用于单节点开发/测试环境。生产环境建议配置高可用和外部数据库。

---

### ✅ 通用前提条件（Fedora & Ubuntu）

```bash
# 关闭防火墙（测试环境）
sudo systemctl stop firewalld 2>/dev/null || sudo ufw disable 2>/dev/null
sudo systemctl disable firewalld 2>/dev/null

# 关闭 SELinux（仅 Fedora/RHEL）
sudo setenforce 0
sudo sed -i 's/^SELINUX=enforcing$/SELINUX=permissive/' /etc/selinux/config 2>/dev/null

# 关闭 swap
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# 启用内核模块（推荐）
sudo modprobe overlay
sudo modprobe br_netfilter

cat <<EOF | sudo tee /etc/modules-load.d/k3s.conf
overlay
br_netfilter
EOF

# 配置 sysctl
cat <<EOF | sudo tee /etc/sysctl.d/k3s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

## A. 在 Fedora 上安装 K3s

### 方法 1：一键脚本安装（推荐）

```bash
# 下载并运行安装脚本（以 root 或 sudo 执行）
curl -sfL https://get.k3s.io | sh -

# 验证服务状态
sudo systemctl status k3s

# 查看节点
sudo k3s kubectl get nodes

# 获取 kubeconfig
sudo cat /etc/rancher/k3s/k3s.yaml

# 配置本地 kubectl（可选）
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config
export KUBECONFIG=~/.kube/config

# 测试
kubectl get pods -A
```

### 方法 2：手动下载二进制（进阶）

```bash
# 下载最新版
wget https://github.com/k3s-io/k3s/releases/latest/download/k3s
chmod +x k3s
sudo mv k3s /usr/local/bin/

# 创建服务目录
sudo mkdir -p /etc/rancher/k3s/
sudo mkdir -p /var/lib/rancher/k3s/

# 创建 systemd 服务
sudo tee /etc/systemd/system/k3s.service <<EOF
[Unit]
Description=Lightweight Kubernetes
Documentation=https://k3s.io
Wants=network-online.target
After=network-online.target

[Install]
WantedBy=multi-user.target

[Service]
Type=exec
EnvironmentFile=-/etc/rancher/k3s/k3s.env
ExecStart=/usr/local/bin/k3s server
KillMode=process
Delegate=yes
LimitNOFILE=1048576
LimitNPROC=infinity
LimitCORE=infinity
TasksMax=infinity
TimeoutStartSec=0
Restart=always
RestartSec=5s
EOF

# 启动服务
sudo systemctl enable --now k3s
```

## B. 在 Ubuntu 上安装 K3s

### 方法 1：一键脚本安装（推荐）

```bash
# 安装 K3s Server（主节点）
curl -sfL https://get.k3s.io | sh -

# 检查状态
sudo systemctl status k3s

# 配置 kubectl
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
kubectl get nodes

# 或复制到用户目录
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config
```

### 方法 2：自定义安装参数

```bash
# 示例：禁用 Traefik，使用 Flannel + Calico，指定数据目录
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--disable traefik --flannel-backend=none --disable-network-policy" sh -

# 示例：使用外部 MySQL 数据库（生产 HA）
curl -sfL https://get.k3s.io | \
  INSTALL_K3S_EXEC="server --cluster-init --datastore-endpoint='mysql://username:password@tcp(hostname:3306)/database-name'" sh -
```

## 七、添加 Worker 节点（Agent）

在其他机器上执行：

```bash
# 获取 Server 节点的 token
sudo cat /var/lib/rancher/k3s/server/node-token

# 在 Agent 节点上运行（替换 SERVER_IP 和 TOKEN）
curl -sfL https://get.k3s.io | K3S_URL=https://<SERVER_IP>:6443 K3S_TOKEN=<TOKEN> sh -

# 示例：
curl -sfL https://get.k3s.io | K3S_URL=https://192.168.1.100:6443 K3S_TOKEN=K10c3f... sh -
```

验证：

```bash
kubectl get nodes
# 应看到 Ready 状态的 agent 节点
```

## 八、常用管理命令

```bash
# 查看服务日志
sudo journalctl -u k3s -f

# 重启 K3s
sudo systemctl restart k3s

# 停止 K3s
sudo systemctl stop k3s

# 卸载 K3s（Server）
/usr/local/bin/k3s-uninstall.sh

# 卸载 K3s（Agent）
/usr/local/bin/k3s-agent-uninstall.sh

# 查看集群信息
kubectl cluster-info

# 查看所有 Pod
kubectl get pods -A

# 查看 Traefik Ingress Controller
kubectl get svc -n kube-system traefik
```

## 九、启用/禁用内置组件

K3s 支持在安装或运行时启用/禁用组件：

```bash
# 安装时禁用 Traefik 和 Local Path Provisioner
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--disable traefik --disable local-storage" sh -

# 启用 Helm Controller（实验性）
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--enable-helm-controller" sh -

# 使用 Docker 作为运行时（不推荐）
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="--docker" sh -
```

> 📝 所有选项可通过 `k3s server --help` 查看。

## 十、部署测试应用

```bash
# 部署 nginx
kubectl create deployment nginx --image=nginx

# 暴露服务
kubectl expose deployment nginx --port=80 --type=LoadBalancer

# 查看服务（Klipper LB 会分配端口）
kubectl get svc nginx

# 访问应用（使用任意节点 IP + 端口）
curl http://<NODE_IP>:<PORT>

# 部署 Ingress（使用 Traefik）
cat <<EOF | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: nginx-ingress
  annotations:
    traefik.ingress.kubernetes.io/router.entrypoints: web
spec:
  rules:
  - host: nginx.local
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: nginx
            port:
              number: 80
EOF

# 添加 hosts 解析后访问 http://nginx.local
```

## 十一、高可用（HA）部署（简要）

### 方式 1：内嵌 etcd（推荐）

```bash
# 第一个 Server 节点
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="server --cluster-init" sh -

# 获取 token
sudo cat /var/lib/rancher/k3s/server/token

# 第二、第三个 Server 节点
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="server --server https://<FIRST_SERVER_IP>:6443 --token <TOKEN>" sh -
```

### 方式 2：外部数据库（MySQL/PostgreSQL）

```bash
# 所有 Server 节点执行
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="server --datastore-endpoint='mysql://username:password@tcp(hostname:3306)/k3s'" sh -
```

## 十二、常见问题与故障排除

### ❌ 节点 NotReady

```bash
# 检查 kubelet 日志
journalctl -u k3s-agent -f

# 检查网络插件（Flannel）
kubectl get pods -n kube-system | grep flannel

# 重启服务
sudo systemctl restart k3s
```

### ❌ Pod 无法拉取镜像

```bash
# 配置国内镜像加速（编辑 /etc/rancher/k3s/registries.yaml）
# 示例：
# mirrors:
#   "docker.io":
#     endpoint:
#       - "https://docker.mirrors.ustc.edu.cn"

sudo systemctl restart k3s
```

### ❌ Traefik 无法访问

```bash
# 检查 Service 类型
kubectl get svc -n kube-system traefik

# 默认是 LoadBalancer，由 Klipper LB 分配端口
# 可通过 NodePort 或 Ingress 访问
```

## ✅ 总结

| 特性 | Kubernetes (kubeadm) | K3s |
|------|----------------------|-----|
| 安装复杂度 | 高（需配置 CRI/CNI/etcd） | 极简（单命令） |
| 资源占用 | 高（推荐 2GB+ RAM） | 低（512MB RAM 可运行） |
| 适用场景 | 生产数据中心 | 边缘、IoT、开发、测试、CI/CD |
| 组件数量 | 多（独立进程） | 少（集成在单二进制） |
| 默认 Ingress | 无（需手动安装） | Traefik（内置） |
| 默认存储 | 无（需安装 CSI） | Local Path Provisioner（内置） |
| 数据库 | etcd（必须） | SQLite（默认）、etcd、MySQL、PostgreSQL |
