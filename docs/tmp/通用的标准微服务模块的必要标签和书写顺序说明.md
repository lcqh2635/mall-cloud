## 一、标签分类

| 分类 | 标签 | 是否必须 |
|------|------|---------|
| 模型版本 | `<modelVersion>` | ✅ 必须 |
| 坐标信息 | `<groupId>`、`<artifactId>`、`<version>` | ✅ 必须（有parent可省略groupId和version） |
| 打包方式 | `<packaging>` | ⚠️ 不写默认jar |
| 父模块 | `<parent>` | 推荐 |
| 模块描述 | `<name>`、`<description>` | 推荐 |
| 子模块聚合 | `<modules>` | 聚合模块必须 |
| 属性定义 | `<properties>` | 按需 |
| 依赖管理 | `<dependencyManagement>` | 按需 |
| 依赖声明 | `<dependencies>` | 按需 |
| 构建配置 | `<build>` | 按需 |

## 二、推荐书写顺序

### 普通业务子模块（如 `services-user`）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">

    <!-- 1. 模型版本，固定写法 -->
    <modelVersion>4.0.0</modelVersion>

    <!-- 2. 父模块 -->
    <parent>
        <groupId>com.urbane</groupId>
        <artifactId>urbane-commerce</artifactId>
        <version>${revision}</version>
        <relativePath>../../pom.xml</relativePath>
    </parent>

    <!-- 3. 当前模块坐标（继承parent后groupId和version可省略） -->
    <artifactId>services-user</artifactId>
    <!-- 4. 打包方式 -->
    <packaging>jar</packaging>

    <!-- 5. 模块描述信息 -->
    <name>services-user</name>
    <description>用户服务：负责用户基本信息管理、收货地址、会员等级、积分及账户安全等用户中心核心功能</description>

    <!-- 6. 模块级属性（如有） -->
    <properties>
        <!-- 仅放当前模块特有的属性 -->
    </properties>

    <!-- 7. 依赖声明 -->
    <dependencies>
        <dependency>
            <groupId>com.urbane</groupId>
            <artifactId>commons-core</artifactId>
        </dependency>
        <dependency>
            <groupId>com.urbane</groupId>
            <artifactId>commons-model</artifactId>
        </dependency>
    </dependencies>

    <!-- 8. 构建配置（如有特殊需求） -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>

</project>
```

### 聚合模块（如 `services`、`commons`）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project>

    <!-- 1. 模型版本 -->
    <modelVersion>4.0.0</modelVersion>

    <!-- 2. 父模块 -->
    <parent>
        <groupId>com.urbane</groupId>
        <artifactId>urbane-commerce</artifactId>
        <version>${revision}</version>
        <relativePath>../pom.xml</relativePath>
    </parent>

    <!-- 3. 当前模块坐标 -->
    <artifactId>services</artifactId>
    <!-- 4. 聚合模块必须是 pom -->
    <packaging>pom</packaging>

    <!-- 5. 描述信息 -->
    <name>services</name>
    <description>业务微服务聚合模块：统一管理所有业务微服务子模块的构建与依赖</description>

    <!-- 6. 子模块列表 -->
    <modules>
        <module>services-user</module>
        <module>services-product</module>
        <module>services-order</module>
        <!-- 其余子模块... -->
    </modules>

</project>
```

### BOM 模块（`urbane-dependencies`）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project>

    <!-- 1. 模型版本 -->
    <modelVersion>4.0.0</modelVersion>

    <!-- 2. 无 parent，独立模块 -->

    <!-- 3. 完整坐标（无parent必须写全） -->
    <groupId>com.urbane</groupId>
    <artifactId>urbane-dependencies</artifactId>
    <version>${revision}</version>
    <!-- 4. BOM 固定为 pom -->
    <packaging>pom</packaging>

    <!-- 5. 描述信息 -->
    <name>urbane-dependencies</name>
    <description>全局依赖版本管理模块：统一锁定项目所有第三方依赖及内部模块版本</description>

    <!-- 6. 版本属性 -->
    <properties>
        <revision>1.0.0-SNAPSHOT</revision>
        <spring-boot.version>3.2.5</spring-boot.version>
        <!-- 其余第三方依赖版本... -->
    </properties>

    <!-- 7. 依赖版本管理 -->
    <dependencyManagement>
        <dependencies>
            <!-- ... -->
        </dependencies>
    </dependencyManagement>

</project>
```

## 三、顺序原则总结

```
modelVersion         ← 第一，固定
parent               ← 第二，确定继承关系
artifactId           ← 第三，模块身份
packaging            ← 第四，紧跟坐标
name / description   ← 第五，模块说明
modules              ← 第六，仅聚合模块有
properties           ← 第七，属性定义
dependencyManagement ← 第八，仅BOM或需要覆盖版本时有
dependencies         ← 第九，实际依赖
build                ← 最后，构建配置
```

> 核心原则：**先定义身份（是谁），再定义关系（从哪来），最后定义行为（做什么）**，层层递进，阅读时自然流畅。
