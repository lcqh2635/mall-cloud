在 Vue3 项目中实现代码生成器（Code Generator）的“生成前预览”功能，核心在于**在浏览器内存中构建一个虚拟文件系统（Virtual File System, VFS）**，并将这个内存数据映射为可视化的**目录树（File Tree）**和**代码预览区（Code Preview）**。

以下是主流的实现方案、技术选型以及核心代码示例。

---

### 一、 核心技术选型

#### 1. 状态管理（虚拟文件系统 VFS）
代码生成前，文件并不存在于真实的磁盘上，而是以 JSON 或对象的形式存在于前端内存中。
*   **推荐**：`Pinia` 或 Vue3 的 `reactive` / `ref`。
*   **数据结构**：通常后端/AI 返回的是**扁平的路径数组**，前端需要将其转换为**树形结构**供 UI 渲染。

#### 2. 文件目录树（File Tree）
*   **UI 组件库**：`Element Plus` (`el-tree`)、`Naive UI` (`n-tree`) 或 `Ant Design Vue` (`a-tree`)。
*   **自定义实现**：使用 Vue3 的**递归组件**（适合高度定制化，如 VS Code 风格的侧边栏）。
*   **图标库**：`lucide-vue-next` 或 `file-icons-js`（用于根据文件后缀名显示对应的 VS Code 图标）。

#### 3. 文件预览（Code Preview）
*   **纯只读预览（轻量、高颜值）**：**Shiki**（VitePress 和 VS Code 都在使用的 TextMate 语法高亮引擎，渲染极美）。
*   **需要编辑/修改（中量级）**：**CodeMirror 6**（支持 Vue/TS 语法高亮和简单的代码提示）。
*   **重型 IDE 体验**：**Monaco Editor**（VS Code 的核心内核，体积较大，支持完整的 IntelliSense）。
*   **Diff 对比（修改前 vs 修改后）**：`Monaco Editor` 的 `DiffEditor` 或 `vue-diff`。

---

### 二、 核心实现步骤与代码示例

假设后端/AI 返回了如下扁平格式的“待生成文件列表”：

```javascript
const rawFiles = [
  { path: 'src/App.vue', content: '<template>...</template>', status: 'new' },
  { path: 'src/main.js', content: 'import { createApp } from "vue"', status: 'new' },
  { path: 'package.json', content: '{...}', status: 'modified' }
]
```

#### 步骤 1：将扁平路径转换为“树形结构”
UI 组件库通常需要树形数据（包含 `children` 属性）。我们需要写一个工具函数进行转换。

```javascript
// utils/fileTree.js
import { ref, computed } from 'vue'

export function useFileSystem(rawFiles) {
  const files = ref(rawFiles)
  const activeFile = ref(null)

  // 扁平转树形结构
  const fileTree = computed(() => {
    const root = { name: 'root', children: {} }
    
    files.value.forEach(file => {
      const parts = file.path.split('/')
      let current = root
      
      parts.forEach((part, index) => {
        if (!current.children[part]) {
          current.children[part] = {
            name: part,
            path: parts.slice(0, index + 1).join('/'),
            isDir: index < parts.length - 1,
            children: {}
          }
        }
        current = current.children[part]
      })
      
      // 将文件内容挂载到叶子节点
      current.content = file.content
      current.status = file.status
    })

    // 递归转换为组件需要的数组格式
    const transform = (node) => {
      return Object.values(node.children).map(child => ({
        label: child.name,
        path: child.path,
        isDir: child.isDir,
        content: child.content,
        status: child.status,
        children: child.isDir ? transform(child) : undefined
      }))
    }

    return transform(root)
  })

  const selectFile = (path) => {
    activeFile.value = files.value.find(f => f.path === path)
  }

  return { fileTree, activeFile, selectFile }
}
```

#### 步骤 2：实现文件目录树 (使用 Element Plus `el-tree`)

```vue
<template>
  <div class="sidebar">
    <el-tree
      :data="fileTree"
      :props="{ children: 'children', label: 'label' }"
      node-key="path"
      @node-click="handleNodeClick"
      default-expand-all
    >
      <template #default="{ node, data }">
        <span class="custom-tree-node">
          <!-- 根据 isDir 或后缀名显示图标 -->
          <el-icon v-if="data.isDir"><FolderOpened /></el-icon>
          <el-icon v-else><Document /></el-icon>
          
          <span :class="{'text-green-500': data.status === 'new', 'text-yellow-500': data.status === 'modified'}">
            {{ node.label }}
          </span>
        </span>
      </template>
    </el-tree>
  </div>
</template>

<script setup>
import { FolderOpened, Document } from '@element-plus/icons-vue'
import { useFileSystem } from '@/utils/fileTree'

const { fileTree, selectFile } = useFileSystem([/* 你的数据 */])

const handleNodeClick = (data) => {
  if (!data.isDir) {
    selectFile(data.path)
  }
}
</script>
```

#### 步骤 3：实现代码预览区 (使用 Shiki)
如果你只需要**纯展示**，强烈推荐使用 `shiki`，它的主题和 VS Code 完全一致。

*安装依赖: `npm i shiki`*

```vue
<template>
  <div class="preview-container">
    <div class="file-header">
      <span>{{ activeFile?.path || '请选择文件' }}</span>
    </div>
    <div class="code-wrapper" v-html="highlightedCode"></div>
  </div>
</template>

<script setup>
import { ref, watch, onMounted, shallowRef } from 'vue'
import { getHighlighter } from 'shiki'

const props = defineProps(['activeFile'])
const highlightedCode = ref('')
const highlighter = shallowRef(null)

onMounted(async () => {
  // 初始化 Shiki 高亮器 (加载 VS Code 暗黑主题)
  highlighter.value = await getHighlighter({
    themes: ['vitesse-dark'],
    langs: ['javascript', 'typescript', 'vue', 'html', 'css', 'json']
  })
})

watch(() => props.activeFile, async (newFile) => {
  if (newFile && highlighter.value) {
    // 根据文件后缀名推断语言
    const lang = getLanguageFromPath(newFile.path)
    highlightedCode.value = highlighter.value.codeToHtml(newFile.content, {
      lang,
      theme: 'vitesse-dark'
    })
  } else {
    highlightedCode.value = ''
  }
}, { immediate: true })

const getLanguageFromPath = (path) => {
  if (path.endsWith('.vue')) return 'vue'
  if (path.endsWith('.js')) return 'javascript'
  if (path.endsWith('.ts')) return 'typescript'
  return 'text'
}
</script>

<style scoped>
.code-wrapper :deep(pre) {
  margin: 0;
  padding: 16px;
  height: 100%;
  overflow: auto;
  background: #121212;
}
</style>
```

### 三、 进阶场景与高级实现

如果你的代码生成器不仅仅是“看看”，还需要更复杂的交互，可以考虑以下进阶方案：

#### 1. 生成前的 Diff 对比（修改确认）
如果生成器会覆盖现有文件，用户需要看到“修改前”和“修改后”的差异。
*   **实现**：使用 `Monaco Editor` 的 `MonacoDiffEditor`。
*   **逻辑**：左侧放原文件内容（Original），右侧放 AI 生成的新内容（Modified）。用户可以在右侧直接微调 AI 生成的代码，然后再点击“确认应用”。

#### 2. 浏览器端沙盒运行 (WebContainers)
如果你想让用户在**生成代码后，直接在浏览器里运行 Vue/Node 项目看效果**（类似 StackBlitz / bolt.new）：
*   **技术**：使用 **WebContainers API** (由 StackBlitz 开源)。
*   **原理**：它可以在浏览器标签页内启动一个完整的 Node.js 运行时环境，你可以把内存中的 VFS（虚拟文件系统）挂载进去，直接运行 `npm install` 和 `npm run dev`，并在 iframe 中预览生成的页面。

#### 3. 目录树的拖拽与重命名
如果允许用户在生成前手动调整 AI 生成的目录结构：
*   不要使用普通的 UI 组件库 Tree，建议使用 **`vuedraggable`** 或 **`dnd-kit`** 结合自定义递归组件，配合 Pinia 实时更新 VFS 中的 `path` 路径。

### 四、 总结与建议

| 需求场景 | 目录树推荐 | 预览区推荐 | 状态管理 |
| :--- | :--- | :--- | :--- |
| **轻量级预览确认** (最常见) | Element Plus `el-tree` | **Shiki** (只读高亮) | Vue3 `reactive` |
| **需要用户二次编辑** | 自定义递归组件 + 右键菜单 | **CodeMirror 6** | Pinia |
| **企业级/IDE级体验** | 自定义实现 (仿 VS Code) | **Monaco Editor** | Pinia + 复杂 VFS 对象 |

**最佳实践提示**：
在前端维护一个 `Map<string, FileObject>` 作为底层数据源（以文件路径为 Key），树形组件和预览组件都通过 `path` 去这个 Map 里读取数据。这样无论是增删改文件，还是重命名，底层数据结构的维护都会非常清晰，不易产生 Bug。
