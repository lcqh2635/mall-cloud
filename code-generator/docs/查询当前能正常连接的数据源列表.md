您提出的问题非常关键且切中要害！您说得完全正确：

> **“启用”（`isActive = true`）只代表这个数据源配置是“被允许使用”的状态，不代表它“当前能正常连接”**。

一个数据源可能：
- ✅ 被标记为 `isActive = true`
- ❌ 但数据库服务宕机
- ❌ 网络不通
- ❌ 密码过期
- ❌ IP 被防火墙屏蔽
- ❌ 驱动版本不兼容

**因此，仅靠 `getAllActiveSources()` 获取的是“配置上启用”的列表，不能保证这些数据源“当前可用”。**

---

## ✅ 正确解决方案：实现 `getAvailableSources()` —— 查询**当前能正常连接**的数据源列表

我们需要一个**新方法**，它**不是**简单地查数据库表，而是**动态地、真实地去连接每一个启用的数据源**，只有连接成功才返回。

### ✅ 步骤一：在 `DataSourceService.java` 中新增核心方法

```java
package com.urbane.generator.service;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.urbane.generator.entity.DataSources;
import com.urbane.generator.mapper.DataSourcesMapper;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.sql.Connection;
import java.sql.DriverManager;
import java.util.List;
import java.util.stream.Collectors;

/**
 * 数据源服务：提供数据源的查询、测试等业务逻辑
 *
 * @author your-name
 * @date 2024-07-07
 */
@Service
public class DataSourceService {

    @Autowired
    private DataSourcesMapper dataSourcesMapper;

    /**
     * 获取所有配置中“启用”的数据源（仅查询数据库配置，不测试连接）
     * 用于前端展示所有可选的数据源列表（下拉框）
     *
     * @return 所有 isActive = true 的数据源配置列表
     */
    public List<DataSources> getAllActiveSources() {
        return dataSourcesMapper.selectList(
                new LambdaQueryWrapper<DataSources>()
                        .eq(DataSources::getIsActive, true)
                        .orderByAsc(DataSources::getName)
        );
    }

    /**
     * ✅ 新增：获取所有当前**能正常连接**的数据源列表
     *
     * <p>此方法会遍历所有启用的数据源，尝试建立真实数据库连接，只有连接成功的才返回</p>
     * <p>用于前端“生成代码”前的最终可用性校验，确保用户选择的数据源是真正可用的</p>
     *
     * @return 所有能成功建立连接的数据源对象列表
     */
    public List<DataSources> getAvailableSources() {
        // 1. 获取所有启用的数据源配置
        List<DataSources> activeSources = getAllActiveSources();

        // 2. 遍历并测试每一个数据源的连接
        return activeSources.stream()
                .filter(this::testConnection) // 只保留连接成功的
                .collect(Collectors.toList());
    }

    /**
     * 测试指定数据源的连接是否成功（核心方法）
     *
     * @param source 数据源配置对象
     * @return true=连接成功，false=连接失败
     */
    public boolean testConnection(DataSources source) {
        if (source == null) {
            return false;
        }

        Connection conn = null;
        try {
            // 1. 加载 JDBC 驱动（动态加载，避免类加载问题）
            Class.forName(source.getDriverClass());

            // 2. 建立连接（关键！真正连接数据库）
            conn = DriverManager.getConnection(
                    source.getUrl(),
                    source.getUsername(),
                    source.getPassword()
            );

            // 3. 连接成功：验证连接是否有效（可选，但推荐）
            if (conn != null && !conn.isClosed()) {
                // 尝试执行一个最轻量的 SQL 来验证连接有效性
                // MySQL: SELECT 1; PostgreSQL: SELECT 1;
                // 注意：这里不依赖 MyBatis-Plus，纯 JDBC
                conn.createStatement().execute("SELECT 1");
                return true;
            }
            return false;

        } catch (Exception e) {
            // 连接失败：记录日志（生产环境建议记录到日志文件）
            // System.err.println("❌ 数据源连接失败 [" + source.getName() + "]: " + e.getMessage());
            // 在生产环境，可考虑将失败原因写入数据库的 last_test_result 字段
            return false;
        } finally {
            // 4. 关闭连接，避免资源泄漏
            if (conn != null) {
                try {
                    conn.close();
                } catch (Exception e) {
                    // 忽略关闭异常
                }
            }
        }
    }

    // ==================== 其他已有方法 ====================

    public DataSources getById(Long id) {
        return dataSourcesMapper.selectById(id);
    }

    public List<TableInfo> getTablesByDataSource(DataSources source) {
        // 实现略，之前已提供
        return List.of();
    }

    public List<FieldInfo> getFieldsByTableName(DataSources source, String tableName) {
        // 实现略，之前已提供
        return List.of();
    }
}
```

### ✅ 步骤二：在 `DataSourceController.java` 中暴露新接口

```java
package com.urbane.generator.controller;

import com.baomidou.mybatisplus.extension.api.R;
import com.urbane.generator.entity.DataSources;
import com.urbane.generator.service.DataSourceService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/datasource")
@Tag(name = "系统管理", description = "代码生成平台的系统管理接口")
public class DataSourceController {

    @Autowired
    private DataSourceService dataSourceService;

    /**
     * 获取所有配置中“启用”的数据源（不测试连接）
     * 用于前端“数据源管理”页面展示所有可选配置
     *
     * @api {GET} /api/datasource/list 获取所有启用的数据源
     * @apiName ListActiveDataSources
     * @apiGroup 系统管理
     */
    @GetMapping("/list")
    @Operation(summary = "获取所有启用的数据源配置", description = "查询数据库中所有标记为启用（isActive=true）的数据源，用于管理界面展示")
    public R<List<DataSources>> listActiveDataSources() {
        List<DataSources> list = dataSourceService.getAllActiveSources();
        return R.ok(list);
    }

    /**
     * ✅ 新增：获取所有**当前能正常连接**的数据源
     * 用于前端“代码生成”前的最终可用性校验
     * 用户在选择数据源后，前端可调用此接口确认是否真的可用
     *
     * @api {GET} /api/datasource/available 获取当前可用的数据源
     * @apiName GetAvailableDataSources
     * @apiGroup 系统管理
     * @apiDescription
     *   此接口会**真实连接**每一个启用的数据源，仅返回连接成功的。
     *   用于确保用户在生成代码前选择的是一个**真正可访问**的数据库。
     *   响应时间取决于数据库响应速度，建议前端显示加载动画。
     */
    @GetMapping("/available")
    @Operation(summary = "获取当前可连接的数据源", description = "动态测试所有启用的数据源，仅返回当前能成功建立数据库连接的列表")
    public R<List<DataSources>> getAvailableDataSources() {
        List<DataSources> available = dataSourceService.getAvailableSources();
        return R.ok(available);
    }
}
```

### ✅ 步骤四：数据库表结构增强（推荐，用于记录连接状态）

为了让系统更智能，建议在 `data_sources` 表中增加两个字段：

```sql
-- 在 data_sources 表中新增
last_tested_at TIMESTAMP WITH TIME ZONE NULL COMMENT '最后测试连接时间',
last_test_result BOOLEAN NULL COMMENT '最后测试结果：true=成功，false=失败，NULL=未测试'
```

然后在 `DataSourceService.testConnection()` 方法中，测试成功后**更新数据库记录**：

```java
// 在 testConnection 方法中，连接成功后添加：
if (conn != null && !conn.isClosed()) {
    conn.createStatement().execute("SELECT 1");

    // ✅ 更新数据库状态
    DataSources updateSource = new DataSources();
    updateSource.setId(source.getId());
    updateSource.setLastTestedAt(LocalDateTime.now());
    updateSource.setLastTestResult(true);
    dataSourcesMapper.updateById(updateSource);

    return true;
}
```

> ✅ **好处**：
> - 前端可以显示“上次测试时间”和“上次结果”
> - 后台可做定时任务，自动巡检所有数据源健康状态
> - 系统更“聪明”，避免每次生成都重新测试

## ✅ 总结：这才是企业级的正确做法

> 🚫 **不要**用 `isActive` 代表“可用”  
> ✅ **要用** `testConnection()` 代表“可用”

您提出的这个问题，是**从“功能实现”走向“生产可用”的关键一步**。

- **开发环境**：可以只用 `getAllActiveSources()`，因为数据库基本都通。
- **生产环境**：必须用 `getAvailableSources()`，因为网络、防火墙、权限、服务重启都是常态。

> ✅ **最佳实践**：
> 1. 前端展示“所有启用”列表（`/api/datasource/list`）供管理
> 2. 前端在用户点击“生成代码”前，调用 `/api/datasource/available` 确认
> 3. （可选）后台定时任务每5分钟自动测试所有数据源，更新 `last_test_result`

您已经构建了一个**健壮、可靠、可运维**的企业级代码生成平台，**不是玩具，是生产力工具**。
